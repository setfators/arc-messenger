## Если браться за следующую итерацию — мой топ-5

1. **★★★ Файлы любых типов через R2** — сейчас вложениями уходят только картинки до 2,5 МБ; документ, архив или видео отправить нельзя. Без R2 остальное упрётся в размер JSON-хранилища.
2. **★★★ Роли и права в каналах** — владелец/модератор, удаление чужих сообщений, «канал только для чтения» для анонсов. Сейчас удалять можно только свои, а канал может удалить любой.
3. **★★ Редактирование сообщений и голосовые** — `msg_edit` с пометкой «изменено» и `MediaRecorder` → opus с кнопкой play в ленте; удобнее текста, когда лень печатать.
4. **★★★ Разбить хранение** — каждое сообщение по-прежнему перезаписывает **весь** JSON: пользователи, все комнаты, токены, настройки. Для 2–3 человек нормально, но это главный предел роста.
5. **★★ Точные непрочитанные на сервере и галочки прочтения** — `lastRead` по комнатам плюс `msg_read`, чтобы счётчики и разделитель «новые» были честными на всех устройствах.

## 4. Надёжность и техдолг

- [ ] **★★★ Разбить хранение.** Сейчас каждое сообщение перезаписывает **весь** JSON: пользователи, все комнаты, токены, настройки. Для 2–3 человек нормально, но это главный предел роста. Варианты: отдельные ключи (`room:<имя>`, `user:<ключ>`), либо D1 (SQL) для сообщений. **(L)**
- [ ] **★★★ Лимиты частоты и размера.** Не больше N сообщений в минуту с человека, ограничение размера кадра WebSocket (сейчас ограничен только текст — 4000 символов, остальное проверяется по факту). Антиспам на будущее. **(S–M)**
- [ ] **★★ Тесты в один запуск.** `cloudflare/test-client.mjs` и `test-server.mjs` уже есть — добавить `npm test`, положить `jsdom` в `devDependencies` и прогнать перед деплоем. Сейчас jsdom ставится руками во временную папку. **(S)**
- [ ] **★★ Версия протокола.** В `hello` отдавать `v`, клиент — свою; старым обо­лочкам (установленный exe) нельзя ломать формат при следующей правке. **(S)**
- [ ] **★★ Отчёты об ошибках.** `window.onerror` и `unhandledrejection` → короткое сообщение на сервер (в лог Durable Object). Сейчас ошибка клиента видна только в консоли, и о ней никто не узнает. **(S)**
- [ ] **★★ Убрать мёртвое и определиться с Rust-версией.** `src/p1.rs`, `src/p2.rs`, `web/p1.html`–`p3.html`, `data/history.jsonl` не используются; `cloudflare/SELF-HOST.md` местами устарел. И главное: две реализации (Cloudflare и Rust) расходятся — либо Rust-вариант поддерживать наравне, либо честно пометить архивным. **(S)**
- [ ] **★ Мониторинг.** В Cloudflare есть observability, но полезно добавить простую страницу «состояние»: сколько пользователей, сообщений, размер базы, ошибки Matrix-моста. **(M)**
- [ ] **★ Ограничить `typing` в каналах.** Сейчас уходит всем подряд в канал; при 8+ участниках будет лишний трафик — слать только тем, у кого канал открыт. **(S)**

## Чего я бы сознательно НЕ делал

- **Сквозное шифрование (E2E).** Для 2–3 человек и сервера, которому и так доверяют, это даёт много сложности (обмен ключами, мультиустройства, восстановление) и мало реальной защиты.
- **Собственный голосовой сервер.** WebRTC через P2P + TURN уже работает; свой медиасервер (SFU) оправдан только при 10+ участниках.
- **Микросервисы и «настоящая» БД «на будущее».** Пока нагрузка — это несколько человек, разбиения хранения на ключи хватит с запасом.
