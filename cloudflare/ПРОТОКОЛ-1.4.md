# Протокол версии 1.4.0 (контракт для правок)

Версия приложения: **1.4.0** (десктоп-оболочка: **1.4.0**).
База — протокол с полем `t`. Новое в 1.4.0: реакции, ответы, картинки-вложения, поиск по истории,
Web Push, поиск людей и карточка профиля, смена пароля/выход со всех устройств/удаление аккаунта.

## Что отдаёт сервер в `hello` (дополнения)

```json
{
  "t": "hello",
  "version": "1.4.0",
  "pushKey": "BAbc...",          // VAPID public key, base64url (uncompressed P-256), если push включён
  "me": { "...": "как раньше" },
  "channels": ["obshiy"],
  "avatars": []
}
```

## 1. Реакции

Клиент → сервер:
```json
{ "t": "msg_react", "room": "obshiy", "id": 42, "emoji": "🔥" }
```
Поведение: одна реакция на пользователя на одно эмодзи; повторный клик тем же эмодзи снимает её.
Сервер проверяет членство в комнате, существование сообщения, эмодзи (1–4 кодовых пункта,
`\p{Extended_Pictographic}`), не больше 20 разных эмодзи на сообщение.

Хранение: `message.reactions = { "🔥": ["anna", "boris"] }` (ключ — эмодзи, значение — имена).

Сервер → комната (канал — всем, личка — только двум участникам):
```json
{ "t": "msg_reaction", "room": "obshiy", "id": 42, "reactions": { "🔥": ["anna"] } }
```
История и новые `msg` уже содержат `reactions` (может отсутствовать).

## 2. Ответы (цитаты)

Клиент → сервер: обычное `msg` с необязательным полем `replyTo` (число — id сообщения):
```json
{ "t": "msg", "room": "obshiy", "text": "согласен", "replyTo": 42 }
```
Сервер проверяет, что сообщение с таким id есть в той же комнате, и кладёт в сообщение снимок:
```json
{ "reply": { "id": 42, "author": "boris", "text": "до 100 символов", "sticker": false } }
```
Если оригинала нет — `reply` не добавляется и сообщение всё равно уходит.

## 3. Картинки-вложения (без R2, куски в хранилище Durable Object)

Загрузка — обычный HTTP POST (не WebSocket, чтобы не упираться в лимит кадра):

```
POST /api/media
x-token: <токен авторизации>
content-type: image/png | image/jpeg | image/webp | image/gif
body: сырые байты, не больше 2 500 000
```
Ответ `200`:
```json
{ "id": "9f3c1a7b2d4e5f60", "url": "/media/9f3c1a7b2d4e5f60", "mime": "image/jpeg", "size": 812345 }
```
Ошибки: `400` (не картинка/пусто/слишком много), `401` (плохой токен), JSON `{ "error": "..." }`.

Отдача: `GET /media/<id>` → байты с `content-type`, `cache-control: public, max-age=31536000, immutable`,
`x-content-type-options: nosniff`, `access-control-allow-origin: *`. `404`, если нет.

Отправка сообщения с картинкой: `msg` с полем `mediaId` (строка id):
```json
{ "t": "msg", "room": "obshiy", "text": "подпись", "mediaId": "9f3c1a7b2d4e5f60" }
```
Сервер проверяет, что вложение существует и загружено этим же пользователем, и кладёт в сообщение:
```json
{ "media": { "id": "9f3c…", "url": "/media/9f3c…", "mime": "image/jpeg", "size": 812345 } }
```
Текст может быть пустым, если есть вложение или стикер.

Ограничения сервера: до 120 последних вложений (старые удаляются вместе с кусками),
кусок 96 КБ, проверка сигнатуры файла (PNG/JPEG/WEBP/GIF), а не только `content-type`.

## 4. Поиск по истории

Клиент → сервер:
```json
{ "t": "search_messages", "q": "слово", "room": "obshiy" }
```
`room` необязателен. Ищем по каналам и по своим личкам; минимум 2 символа, максимум 100.
Новые сообщения — первыми, не больше 40 попаданий, текст обрезан до 200 символов.

Сервер → клиенту:
```json
{ "t": "search_results", "q": "слово", "hits": [
  { "room": "obshiy", "id": 42, "author": "boris", "text": "…слово…", "ts": 1700000000000 }
] }
```

## 5. Web Push (уведомления при закрытом приложении)

`hello.pushKey` — публичный VAPID-ключ (base64url, несжатая точка P-256). Если его нет — push недоступен.

Клиент → сервер:
```json
{ "t": "push_subscribe", "subscription": {
    "endpoint": "https://fcm.googleapis.com/…",
    "keys": { "p256dh": "…", "auth": "…" } } }
```
Сервер отвечает `{ "t": "notice", "text": "Уведомления включены" }` или `{ "t": "error", "text": "…" }`.
Отписка: `{ "t": "push_unsubscribe" }` → `notice`.

Сервер отправляет **пустой** push (без тела) тем получателям, у кого нет открытых сокетов:
для лички — собеседнику, для канала — всем подписанным, кроме автора.
Заголовки: `TTL: 3600`, `Urgency: normal`, `Authorization: vapid t=<JWT ES256>, k=<pushKey>`.
`404`/`410` от push-сервиса → подписку удаляем.

Service worker ловит `push` и показывает системное уведомление «Arc — новое сообщение»
(без текста сообщения), клик открывает/фокусирует окно приложения.

## 6. Бейдж непрочитанных для десктопа

Мост, который даёт `preload.js`:
```js
window.messengerDesktop = {
  version: '1.4.0',              // версия оболочки
  setBadge: (count) => {},        // число непрочитанных, 0 — снять
  checkUpdates: () => Promise,    // проверить обновления вручную
}
```
Клиент вызывает `window.messengerDesktop?.setBadge(totalUnread())` при каждом изменении счётчика.

## 7. Уже готовое на сервере, нужен только интерфейс

- `{ "t": "search_users", "q": "..." }` → `{ "t": "user_search", "q": "...", "results": [ { name, displayName, avatarUrl, online, friend, pending: '' | 'in' | 'out' } ] }`
- `{ "t": "user_card", "name": "boris" }` → `{ "t": "user_card", "user": { name, displayName, bio, avatarUrl, accent, color, online, status, joined, friend, pending, voiceRoom } }`
- `{ "t": "password_change", "old": "...", "new": "..." }` → `notice` / `error`
- `{ "t": "logout_all" }` → `notice` (текущая сессия остаётся)
- `{ "t": "account_delete", "password": "..." }` → `account_deleted` (клиент возвращается на экран входа)
