# Свой сервер (self-host) и мост в Matrix

Всё, что ниже, уже поддержано в приложении — нужен только адрес сервера и,
для Matrix, токен. Пароли нигде не хранятся.

---

## 1. Три способа держать сервер у себя

### A. Свой аккаунт Cloudflare (проще всего, бесплатно)

Данные живут в вашем личном Durable Object, чужого аккаунта в цепочке нет.

```bash
cd cloudflare
npx wrangler login                 # вход в СВОЙ аккаунт
npx wrangler deploy                # получите адрес вида https://<имя>.<поддомен>.workers.dev
```

Свой домен (необязательно): Dashboard → Workers & Pages → rust-messenger →
Settings → Domains & Routes → Add custom domain.

Что где лежит:
- каналы, сообщения, профили, аватары, стикеры — в Durable Object `ChatHub`
  (SQLite-хранилище Cloudflare, миграция `v1` в `wrangler.jsonc`);
- страницы и иконки — в `public/` (статический биндинг `ASSETS`);
- ничего не нужно держать включённым у себя дома.

Ограничения бесплатного плана: 100 000 запросов в сутки, WebSocket-сообщения
считаются запросами. Для двух-десяти человек этого хватает с запасом.

### B. Полностью локальный сервер (VPS или домашний ПК)

Тот же код запускается без Cloudflare через `wrangler dev` — данные пишутся
в локальную папку `.wrangler/state`, наружу ничего не уходит.

```bash
cd cloudflare
npm install
npx wrangler dev --ip 0.0.0.0 --port 8787
```

Дальше нужен постоянный вход снаружи: обратный прокси (Caddy или nginx) и
HTTPS-сертификат, иначе браузер не даст WebSocket с `https`-страницы.

Caddy — самый короткий вариант, `/etc/caddy/Caddyfile`:

```
chat.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

Чтобы процесс не падал после выхода из SSH:

```bash
npm i -g pm2
pm2 start "npx wrangler dev --ip 127.0.0.1 --port 8787" --name messenger
pm2 save && pm2 startup
```

Проверка живости: `curl https://chat.example.com/health` → `ok`.

Важно: `wrangler dev` держит данные в локальной папке, резервная копия —
это копия каталога `.wrangler/state`. Остановили и удалили папку — потеряли
историю, поэтому её стоит складывать в бэкап (например, `rsync` раз в сутки).

### C. Свой аккаунт Matrix вместо собственного сервера

Если сервер держать не хочется, а данные — хочется: поднимите аккаунт на
любом home-сервере Matrix (matrix.org, олдскул-хостинги, свой Synapse) и
подключите мост — сообщения канала будут дублироваться в комнату Matrix.
Это раздел 2.

---

## 2. Мост в Matrix

Работает в две стороны: из мессенджера в комнату и из комнаты в канал.
Пароль не нужен, только access token.

### Как получить данные

1. **Home-сервер** — адрес, на котором зарегистрирован аккаунт, например
   `https://matrix.org`.
2. **Access token** — в Element: `Настройки` → `Помощь и о программе` →
   строка `Access token`. Или запросом:

   ```bash
   curl -X POST https://matrix.org/_matrix/client/v3/login \
     -H 'Content-Type: application/json' \
     -d '{"type":"m.login.password","identifier":{"type":"m.id.user","user":"ИМЯ"},
          "password":"ПАРОЛЬ"}'
   ```

   В ответе поле `access_token` (вид `syt_…`). Этот токен = полный доступ
   к аккаунту, поэтому он хранится на сервере мессенджера, а не в браузере.
3. **Комната** — `!abcdefgh:matrix.org`. Идентификатор виден в Element:
   `Настройки комнаты` → `Дополнительные настройки` → `Внутренний ID`.
   Можно вписать и адрес вида `#general:matrix.org` — сервер сам найдёт
   внутренний ID.
4. **Канал мессенджера** — куда складывать входящие (по умолчанию `obshiy`).

### Включение

`Настройки` → вкладка `Мосты и сервер` → раздел `Мост в Matrix`:
заполнить поля, нажать `Проверить связь` (проверит токен запросом `whoami`),
затем `Сохранить и включить`.

- `Проверить связь` — покажет ваш Matrix-идентификатор, если токен рабочий.
- `Забрать сообщения` — заберёт новое из комнаты сразу, не дожидаясь таймера.
- `Выключить мост` — перестаёт и отправлять, и принимать.
- Направление: только туда, только оттуда или в обе стороны.
- Приписка (например `[MX] `) помогает отличить сообщения из Matrix.

### Как это устроено

- Исходящие: сообщение канала уходит в комнату через
  `PUT /_matrix/client/v3/rooms/{roomId}/send/m.room.message/{txnId}`.
- Входящие: раз в минуту (и по кнопке) сервер вызывает `/sync` с
  сохранённого `since`-токена, новые `m.room.message` превращает в сообщения
  канала от имени `Matrix · @user:server`.
- Проверка токена: `GET /_matrix/client/v3/account/whoami`.
- Всё это в `src/matrix.js`, настройки — в поле `matrix` хранилища `ChatHub`.

Ограничения, о которых стоит знать:
- вложения и стикеры в Matrix не пересылаются, только текст;
- правки и удаления сообщений в Matrix не отражаются в мессенджере;
- шифрованные (E2EE) комнаты не поддерживаются — мост читает только
  открытые комнаты.

## 3. Как направить приложение на свой сервер

Порядок поиска адреса в десктопной версии:

1. `server.json` в папке профиля приложения:
   `%APPDATA%\messenger-desktop\server.json` → `{"url":"https://chat.example.com"}`
2. переменная окружения `MESSENGER_SERVER_URL`;
3. стандартный адрес Cloudflare;
4. в самом приложении: `Настройки` → `Мосты и сервер` → `Свой сервер` →
   адрес → `Сохранить и перезапустить`. Кнопка `Вернуть стандартный`
   возвращает адрес Cloudflare.

Папка профиля на Windows: `C:\Users\<имя>\AppData\Roaming\messenger-desktop`
(там же `update.json` с каналом обновлений).

## 4. Канал обновлений

Приложение проверяет обновления при запуске и раз в 6 часов, качает в фоне и
ставит при перезапуске (`electron-updater`, generic-провайдер).

Что нужно на сервере — два файла в одной папке:

```
updates/
  latest.yml                      # манифест: версия, имя файла, sha512, размер
  Messenger-Setup-1.2.0.exe       # сам установщик
```

`latest.yml` создаётся сборкой автоматически (`desktop/dist/latest.yml`),
копировать его руками не надо — только перенести вместе с exe.

Порядок выпуска новой версии:

```bash
cd cloudflare/desktop
npm version 1.3.0 --no-git-tag-version   # поднять версию
npx electron-builder --win nsis          # dist/latest.yml + dist/Messenger-Setup-1.3.0.exe
```

Затем оба файла — в папку `updates/` на сервере, который отдаёт их по HTTPS.
Проще всего:

```bash
# на сервере, в папке с файлами
python3 -m http.server 8080            # только для проверки, без HTTPS
```

Рабочий вариант — тот же Caddy:

```
updates.example.com {
    root * /var/www/updates
    file_server
}
```

Адрес канала указывается в приложении: `Настройки` → `Мосты и сервер` →
`Канал обновлений` (или `update.json` → `{"feed":"https://updates.example.com/"}`,
или переменная `MESSENGER_UPDATE_URL`). Адрес должен заканчиваться слэшем.

Важно про раздачу с Cloudflare Workers: файлы в `public/` ограничены 25 МиБ,
поэтому установщик (≈116 МБ) туда не положить — на воркере лежит только
`latest.yml` (`/updates/latest.yml`), а сам `.exe` кладут на обычный
HTTP-хостинг и путь к нему прописывают в `latest.yml` полным адресом:

```yaml
path: https://files.example.com/Messenger-Setup-1.2.0.exe
files:
  - url: https://files.example.com/Messenger-Setup-1.2.0.exe
    sha512: <оставить из сборки>
    size: 121488556
```

Проверка, что канал живой: `curl https://updates.example.com/latest.yml` —
должен вернуться этот YAML, а не HTML и не 404.

## 5. Что проверить после переезда

- `GET /health` → `ok`;
- регистрация и вход (данные на новом сервере свои, старые не переезжают);
- WebSocket: в интерфейсе появляются каналы;
- голос на двоих и демонстрация экрана;
- `Настройки` → `Мосты и сервер`: проверка Matrix и канала обновлений.

## 6. Чего в self-host пока нет

- автоматического переноса истории со старого сервера (экспорт в файл и
  импорт не сделаны — только ручная копия состояния `.wrangler/state`
  или дампа Durable Object);
- ограничения числа попыток входа и капчи;
- резервного копирования по расписанию — делать внешними средствами;
- работы без HTTPS (браузер не даст микрофон и WebSocket из `http://`,
  кроме `localhost`).
